# 工程推进计划（Step-by-Step）

本文件描述从当前脚手架到产出完整实验结果的推进路线。每个阶段包含:**目标 → 操作命令 → 验证关卡(Gate) → 已知风险 → 完成标准**。按顺序推进,只有通过当前阶段的 Gate 才进入下一阶段。

> 约定:所有 Python 通过 conda 环境运行。下文假设环境名为 `ijepa`(见阶段 0)。
> 工作目录始终为仓库根 `~/Desktop/research`。

---

## 阶段总览

| 阶段 | 名称 | 产出 | 预估 |
|------|------|------|------|
| 0 | 环境搭建 | 可运行的 conda 环境 + 测试通过 | 0.5h |
| 1 | 权重获取与加载验证 | 4 个 encoder 都能 load | 1–3h(下载为主) |
| 2 | 特征抽取冒烟 + 全量 | `features/cache/` 缓存 | 1–2h |
| 3 | Part A:SVD 谱分析 | `results/<ds>/svd/` | 0.5h |
| 4 | Part B:SVM 线性探针 | `results/<ds>/svm/` | 0.5–1h |
| 5 | 连接分析(SVD↔SVM) | `results/<ds>/connect/` | 0.2h |
| 6 | CIFAR-10 交叉验证 | 第二数据集结果 | 1–2h |
| 7 | 可选 Part C / D | viewpoint / perturbation 结果 | 各 1–2h |
| 8 | 图表与报告 | 论文用图 + 结论表 | 持续 |

**关键风险点**:阶段 1 的 checkpoint 键名重映射(I-JEPA / MAE / SimCLR 官方权重的 state_dict 结构各异),这是最可能卡住的地方,文档为它单列了排查步骤。

## 阶段 1 — 权重获取与加载验证 ⚠️ 关键阶段

**目标**:让 4 个 encoder 都能成功 `build_encoder` 并输出正确维度的特征。

### 1.1 下载权重

放到 `./weights/`(路径见 [configs/encoders.yaml](../configs/encoders.yaml)):

| Encoder | 文件名 | 来源 |
|---------|--------|------|
| ResNet-18(监督) | 无需下载 | torchvision 自动 |
| I-JEPA ViT-S/16 | `ijepa_vits16.pth` | https://github.com/facebookresearch/ijepa |
| MAE ViT-S/16 | `mae_vits16.pth` | https://github.com/facebookresearch/mae |
| SimCLR ResNet-18 | `simclr_resnet18.pth` | https://github.com/google-research/simclr 或社区 PyTorch 移植 |

> 注意:I-JEPA 官方多为 ViT-H/14、ViT-L 等大模型。若找不到 ViT-S/16,有两个选择:
> (a) 改用官方提供的最小规格,并同步修改 `configs/encoders.yaml` 的 `arch` 与 `feature_dim`、以及 MAE 侧保持同架构以维持对照;
> (b) 在提案中说明用 ViT-B/16 作为 I-JEPA/MAE 的共同骨干。**两者必须同架构**,这是对照实验的前提。

### 1.2 验证加载

```bash
python scripts/00_download_weights.py
```

### 1.3 排查 checkpoint 键名(几乎一定会遇到)

`vit.py` / `resnet.py` 里的键名重映射是基于常见结构的"尽力而为"。真实权重大概率需要微调。排查方法:

```bash
python - <<'PY'
import torch
ck = torch.load("weights/ijepa_vits16.pth", map_location="cpu")
# 找到真正的 state_dict 层级
print(type(ck), list(ck.keys())[:10] if isinstance(ck, dict) else "tensor")
sd = ck.get("target_encoder", ck.get("encoder", ck.get("model", ck)))
print("示例键名:")
for k in list(sd.keys())[:15]:
    print("  ", k, tuple(sd[k].shape))
PY
```

把打印出的真实前缀,对照 timm ViT 的命名(`patch_embed.proj.weight`、`blocks.0.attn.qkv.weight`、`norm.weight` 等),据此修改:
- I-JEPA → [src/encoders/vit.py](../src/encoders/vit.py) 的 `_remap_jepa_keys`
- MAE → 同文件 `_remap_mae_keys`
- SimCLR → [src/encoders/resnet.py](../src/encoders/resnet.py) 的 `_load_simclr_state_dict`

**Gate 1**:
- [ ] `00_download_weights.py` 末尾打印 `All encoders loaded successfully.`
- [ ] 每个 encoder 的 `feature_dim` 正确(ResNet=512,ViT=384)
- [ ] 快速健全性检查:同一张图两次前向输出一致(已冻结、eval),且不同图输出不同

```bash
python - <<'PY'
import torch
from src.encoders import build_encoder
enc = build_encoder("ijepa_vits16", device="cpu")
x = torch.randn(2,3,224,224)
y = enc(x)
print("shape", tuple(y.shape), "| 两次一致:", torch.allclose(enc(x), y))
PY
```

**已知风险**:
- 加载后 `missing/unexpected keys` 太多 → 前缀没剥干净,回到 1.3。
- ViT `forward_features` 返回已 pool 的 2D 张量 → 代码已兼容,但要确认 pool 语义(I-JEPA 无 CLS,用 patch token 均值)。
- SimCLR 权重若来自 MoCo 风格仓库,前缀可能是 `encoder_q.`,已在剥离列表中。

**完成标准**:4 个 encoder 都能稳定输出特征。**这是后续一切的前提,不要带病推进。**

## 阶段 2 — 特征抽取

**目标**:对每个 encoder × 每个 split 抽取并缓存原始特征。

### 2.1 先冒烟(强烈建议)

用极小批量 + 单 encoder 跑通流程,避免在全量上才发现问题:

```bash
python scripts/01_extract_features.py \
    encoders=[ijepa_vits16] features.batch_size=32 dataset.num_workers=2
```

> 说明:覆盖 `encoders` 为单元素列表可只测一个。若 CLI 解析列表不便,临时改 `configs/default.yaml` 也可。

检查 `features/cache/` 是否生成 `stl10__ijepa_vits16__train.pt` / `__test.pt`。

### 2.2 全量抽取

```bash
python scripts/01_extract_features.py            # STL-10,全部 4 个 encoder
# 显存不足就调小:features.batch_size=128 features.amp=true
```

**Gate 2**:
- [ ] `features/cache/` 下有 4 encoder × 2 split = 8 个 `.pt`
- [ ] 维度正确:STL-10 train=5000、test=8000;ResNet 原始 dim=512、ViT=384
```bash
python - <<'PY'
from src.features import load_bundle
for enc in ["resnet18_supervised","simclr_resnet18","ijepa_vits16","mae_vits16"]:
    for sp in ["train","test"]:
        b = load_bundle("features/cache", enc, "stl10", sp)
        print(f"{enc:24s} {sp:5s} -> {tuple(b.features.shape)}")
PY
```

**已知风险**:
- STL-10 首次会自动下载(~2.5GB)到 `./data/`,确保磁盘和网络。
- `num_workers` 过高在 Mac 上可能卡死,调到 2–4。
- 抽取一次后特征已缓存,后续分析不再跑 encoder;改预处理参数无需重抽。

## 阶段 3 — Part A:SVD 谱分析

**目标**:得到 RankMe 有效秩、PCA 参与率、Two-NN 本征维数、维度坍缩计数。

```bash
python scripts/02_svd_analysis.py
```

**Gate 3**:
- [ ] 生成 `results/stl10/svd/svd_summary.json`、`spectra.npz`、`singular_spectra.png`
- [ ] 数值合理性:RankMe ∈ (1, 384];坍缩维数不应等于 ambient(否则全坍缩,检查预处理)
- [ ] 看图:谱应单调下降;不同 encoder 衰减速率有差异

**结果解读要点**(写报告用):
- 重点看 **I-JEPA vs MAE**(同架构):谁的 RankMe 更高?
- `curvature_gap_rankme_minus_twonn` 大 → 流形有明显曲率,线性子空间近似差。

**已知风险**:若所有 encoder 的谱几乎重合,检查是否随机投影把信息抹平了——可临时 `features.random_projection.enabled=false` 对比(但跨维度比较会失去公平性,仅作诊断)。

## 阶段 4 — Part B:SVM 线性探针

**目标**:每个 encoder 的线性可分性诊断(准确率、间隔、支持向量、混淆)。

```bash
python scripts/03_svm_probe.py
```

**Gate 4**:
- [ ] 生成 `results/stl10/svm/svm_summary.json` 及各 `confusion_<encoder>.png`
- [ ] 准确率合理(STL-10 冻结特征线性探针通常 0.6–0.9 区间,视 encoder 而定)
- [ ] `mean_margin`、`support_vector_fraction` 有跨 encoder 差异

**已知风险**:
- 线性 SVM 在 5000×384 上训练应是秒级~分钟级;若极慢,确认 `svm.max_samples_fit` 生效。
- 若准确率接近随机(0.1),多半是特征加载/标签错位,回阶段 2 核对。

## 阶段 5 — 连接分析(核心贡献)

**目标**:把 Part A 的有效秩与 Part B 的间隔关联起来,并给出 MAE/I-JEPA 架构对照的差值。

```bash
python scripts/04_connect_analysis.py
```

**Gate 5**:
- [ ] 生成 `results/stl10/connect/connect_report.json`、`rank_vs_margin.csv`、`rank_vs_margin.png`
- [ ] 日志打印 Pearson/Spearman 相关与 `I-JEPA - MAE` 的 ΔRankMe / ΔMargin / ΔAcc

**注意**:只有 4 个 encoder,相关系数仅作**描述性**陈述,严禁写成因果。报告里强调"structural correlation, not causal"。
